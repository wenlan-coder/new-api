## 关键问题
1. 配置项命名采用 `group_monitor_link`。
2. 导航文案采用“Group Monitor”作为英文 key，中文显示“分组监控”。
3. 仅做最小改动，不新增内部页面。
4. 保留上一版逻辑：导航开关只控制显示开关，外链地址仍在原配置入口维护。
5. 配置实际存储在 `options` 表，key 为 `general_setting.group_monitor_link`。
6. 服务条款采用 `legal.terms_of_service`，跟用户协议、隐私政策同属 `legal` 配置。
7. 服务条款内容非空时才显示入口。
8. 认证页底部条款提示必须整体走 i18n，避免前半句英文、链接中文的混合显示。
9. 当前系统名称只有一个 `SystemName` / `system_name`，没有中文名称和英文显示名称的双字段模型。
10. 本次需求需要只保留中文、英文两种前端语言，并支持系统名称单独设置英文显示名称。
11. 法律文档当前只有中文/默认字段：`legal.user_agreement`、`legal.privacy_policy`、`legal.terms_of_service`。
12. 法律文档英文内容建议新增并行字段：`legal.user_agreement_en`、`legal.privacy_policy_en`、`legal.terms_of_service_en`。
13. 本次发布保留官方更新检测源，当前官方最新 release 为 `v1.0.0-rc.11`，自定义发布版本号设为 `v1.0.0-rc.11-transnova.1`。

## 已做决策
| 决策 | 理由 |
|------|------|
| 复用“文档链接”的外链展示模式 | 用户明确要求和文档一样，最小改动 |
| 将配置输入放在文档链接附近 | 用户明确要求放在文档链接页面 |
| 导航模块新增 `groupMonitor` 布尔开关 | 复用现有 `HeaderNavModules` 结构，不引入新机制 |
| 服务条款复用现有法律文档模式 | 最小改动，避免引入新配置系统 |
| 系统名称改造先走设计确认 | 涉及后端配置、状态接口、前端缓存、设置页和语言包范围，属于非琐碎改动 |
| 保留 `SystemName` 作为中文/默认系统名称，新增 `SystemNameEn` | 兼容旧数据；英文名为空时回退默认名 |
| 隐藏 `fr/ja/ru/vi` 而不删除文件 | 用户确认旧语言可隐藏，不需要单独清理 |
| 法律文档保留旧字段作为中文/默认内容，新增英文内容字段 | 兼容已有配置；英文内容为空时可回退中文/默认内容 |
| 自定义 Docker 版本基于官方 release 加后缀 | 保留官方更新检测语义，同时能区分本地定制版本 |
